## Answers to the four specific questions

### Q1. Does the Spearman-Karber (SK) reading hold for this BSC definition? Only conditionally; the protocol's gate [0.1, 0.9] is too weak
Facts. BSC_arm = mean over units of (1[left correct] + 1[right correct])/2 with rho_u ~ U[a,b] estimates mean_rho of the side-averaged hit curve h(rho), i.e. the AREA under h over [a,b] divided by (b-a). That is always a valid, interpretable quantity ("mean hit rate over the stimulus family"). It equals (rho_th - a)/(b - a) - and a shift DeltaBSC x 0.14 m equals a threshold shift - only if h = 1 at/below a and h = 0 at/above b for both arms and h is monotone. Numeric check (rt_r2.py, logistic h, true shift 20 mm, expected dBSC 0.143): threshold in the middle: exact (20.0 mm). Threshold near the edge, BSC0 = 0.89: implied shift 12-14.5 mm (30-40 % under-read); BSC0 = 0.79 with width 1 cm: 17.4 mm. A non-monotone h (hit halves for rho < 0.25, as from D = 0 ties/both DNa02 firing at very near range or when sin pushes the bearing across the midline) lowers BSC0 from 0.46 to 0.36 with no threshold change. Side asymmetry is fine (side-averaged area = mean of the two side thresholds). The |az| spread (8-12 deg) just broadens h by about +-0.5 cm (0.13 mV/deg x 2 deg / 0.45 mV per 2 cm) - harmless.
Problems: (a) the gate looks at BSC, not at the edges: BSC = 0.1 or 0.9 can be a curve that never reaches 1 at a or never reaches 0 at b; (b) in the classification list UNMEASURABLE is checked AFTER SUPPORTED/DETECTABLE/HARMFUL/EQUIVALENT, so an edge-censored arm can be classified SUPPORTED with a metric that no longer reads as "1 cm"; (c) SESOI "0.07 = 1 cm" is only literally true under the edge condition; (d) the 0D variants (|az| 4-8 with A up to 4 deg: bearing crosses the midline) and very near rho will be non-monotone by design; (e) no analogue of R3 for range D - if pilot DATA stationary BSC lies outside [0.1, 0.9] there is no re-centring rule (probe suggests threshold ~0.285 m and BSC ~0.45, fine, but the rule is missing).
Fix (M-A): define the primary as "mean side-correct rate over the stimulus family" and call the shift reading a derived quantity valid only if, per arm, hit rate in the nearest 15 % of rho_u >= 0.9 AND in the farthest 15 % <= 0.1 (edge test, computed per arm incl. after-shift arm) and a monotonicity check (e.g. Spearman(hit, rho) < -0.5 in each arm); otherwise report area differences without the "cm" gloss; apply the gate BEFORE classification; add R3D (re-centre range D around the pilot DATA SK threshold, width 0.14 m, if pilot stationary BSC is outside [0.2, 0.8]); report hit curves binned in rho (7 bins) for every arm.

### Q2. Does J_shuf answer the C4 'peak' fairness concern? Yes at stimulus level, partly at neuron level; S2 is still peak-unfair
- J_shuf has exactly the sin theta multiset in the window (same peaks, same RMS, zero window mean), so for a MEMORYLESS stage the sinusoid and J_shuf are identical in expectation (the renderer depends only on theta, pixel noise is per frame). Hence TH must give S1 = 0 (EQUIVALENT) - add that as a pre-registered positive control (TH sin - TH J_shuf), failing it signals a pipeline order/state bug.
- But J_shuf is maximally mismatched in velocity: RMS theta-dot of a permuted sinusoid is 12x (f = 1 Hz) and 3x (f = 4 Hz) that of the sinusoid (rt_r2.py). The SNN integrates (tau_m 20 ms; adaptation 300 ms), so a positive S1 for the SNN will largely mean "the membrane low-passes a white permutation and loses its peaks", i.e. a bandwidth/smoothing effect, not periodicity. S1's label ("temporal structure vs amplitude distribution") is acceptable, but the wording in conclusions must not read S1 > 0 as "frequency tuning". Add a block-permuted sinusoid (blocks of ~50 ms, whole blocks permuted; same multiset, local waveform preserved) as an exploratory bridge between sin and J_shuf.
- S2 (J_vel) is still not peak-fair: accepted J_vel windows have median max|theta|/A = 1.24 (0.5 Hz), 1.44 (1 Hz), 1.63 (2 Hz), 1.80 (4 Hz) (5-95 %: up to 2.27) versus 1.00 for sin. State that S2 jitter beating the sinusoid can be a tail effect; interpret S2 together with S1 and with TH (TH response to J_vel vs sin gives the pure tail effect for a memoryless detector) - i.e. report S2 for TH as the calibration of "what peak exposure alone does".

### Q3. J_vel rejection rule (+-20 % window RMS velocity): bias?
Rejection is symmetric about the target ratio, so it does not bias the velocity ratio itself, but it truncates the ensemble: acceptance 33 % (0.5 Hz), 53 % (1 Hz), 76 % (2 Hz), 93 % (4 Hz) (rt_r2.py, rescaled as in §3). Selection mildly removes low-ratio (ramp-like, high-peak) realisations: median window max|theta|/A falls 1.32 -> 1.24 at 0.5 Hz (-6 %), 1.47 -> 1.44 at 1 Hz, none at >= 2 Hz; the 95th percentile drops 1.96 -> 1.71 at 0.5 Hz. So J_vel at low f is slightly LESS peaked than an unselected draw - conservative against a "jitter beats sinusoid" finding, not toward it. Acceptable. Requirements: (i) specify that the velocity check uses np.gradient on the full 300-frame series restricted to frames 100-299 (as for sin), (ii) record number of draws and accepted ratio per realisation, (iii) 1000-draw cap is ample (P(fail) < 1e-100), (iv) state in the report that the +-20 % tolerance allows a velocity mismatch of up to 20 % per realisation (mean ~0) and that S2 is not a perfectly velocity-matched contrast.

### Q4. Hierarchical bootstrap pairing with DATA
Design: draw 10 instances with replacement, then units within each drawn instance; "the same unit list is used for the DATA term". This is coherent: DATA is evaluated on exactly the resampled units, so paired contrasts cancel the shared stimulus/noise component. Remarks:
- DATA is a single network and instance is a function of (u - first) mod 10, so each instance is a fixed unit subset; DATA's term in S3/S4 is re-evaluated on a subset with duplicates and drops units of undrawn instances - correct and slightly conservative, but state it. Percentile CI with 10 clusters is generally anti-conservative in theory; in a toy (rt_r2.py, G = 10 instances, SD_between 0.05, SD_within 0.3, 20 units each) coverage was 0.97 (not a problem); the real instances behave ~like one network (FINAL_REPORT section A), so the instance level contributes little. Still, add the per-instance Delta table and DATA's rank among 10 + 10 instances (permutation-style) as the primary wiring-specificity statement, since a bootstrap over instances cannot say whether DATA lies outside the shuffle distribution.
- n is clamped but need not be a multiple of 10: define the unit list per instance (ceil/floor) and state it.
- Criteria re-estimated per resample: for SNN/TH/P c = 0 always, for LIN depends on the drawn no-target units; use the same drawn units for the no-target trials (they are per unit, so yes).

## MAJOR (fix before pilot)

M-A. SK/gate/classification order (see Q1). Apply measurability (edge + monotonicity) before classification; area-reading vs shift-reading; R3D.

M-B. Classification order makes EQUIVALENT unreachable when the CI excludes zero. "First matching rule wins": SUPPORTED -> DETECTABLE-BELOW-SESOI (CI95 > 0) -> HARMFUL (CI95 < 0) -> EQUIVALENT (CI90 within +-0.07). With enough n a tiny positive difference (say 0.02, CI 0.01-0.03) is DETECTABLE-BELOW-SESOI and never EQUIVALENT; a tiny negative one is HARMFUL (even though |est| << SESOI). Consequences: F-b ("S1 or S2 EQUIVALENT or negative"), F-c (S6 EQUIVALENT or negative), F-d (both EQUIVALENT or negative) can be dodged by precision; "negative" is undefined (est < 0? HARMFUL?). Fix: SUPPORTED (CI95 > 0, est >= 0.07) > HARMFUL (CI95 < 0, est <= -0.07) > EQUIVALENT (CI90 inside +-0.07, both arms measurable; additionally flag "detectable" if CI95 excludes 0) > DETECTABLE-BELOW-SESOI > UNMEASURABLE > INCONCLUSIVE; define "negative" = HARMFUL or est < 0 with EQUIVALENT absent, or just drop it and use the classes.

M-C. Cross-system comparison is back in F-c. F-c says "S5 SUPPORTED with est >= Delta1": S5 is Delta on range C (k in a 0.16-0.20 wide k window, fraction of a contrast range) and Delta1 on range D (fraction of 0.14 m); the two BSC scales are arbitrary (range widths, one geometric one photometric), which is exactly my r1 C2 objection. Fix: delete that clause or convert both shifts to a common unit before comparing, e.g. relative shift in effective stimulus strength: threshold shift expressed as the change in encoder drive at threshold (12*g in mV or in E = sum c.S units) or as a fractional change of the stimulus parameter (delta_rho/rho_th, delta_k/k_th) with the same bootstrap; S5 as "own-range test" is otherwise fine. Also add S5 to R2 (P's SD) so power is reported.

M-D. TH is a max-detector at c = 0, so S6 is structurally biased towards "control benefits more". With c = 0, TH reports as soon as a SINGLE frame has 12 g_s > theta_TH (window mean of the positive part is > 0 iff any frame exceeds). The SNN needs >= 1 net DNa02 spike after tau_m 20 ms integration (and recurrent/adaptation). R4 matches the two on STATIONARY BSC only (one scalar, 60 pilot units, SE of BSC ~ 0.05 = 0.7 cm = 0.15 mV, comparable to the effect), so the match tells nothing about integration. Under peaky motion (J_shuf, J_rms, J_vel) isolated single-frame peaks trigger TH but not the SNN. Therefore S6 "EQUIVALENT or negative" (F-c) is the expected outcome for reasons that are not "SNN dynamics vs threshold". Fix: add TH_LP (the same threshold after a first-order low-pass tau 20 ms on 12 g_s, optionally + adaptation b 0.5 mV, tau 300 ms = single-LIF surrogate) with theta chosen by the same R4 rule; make S6 use TH_LP (keep TH as a labelled variant); report TH vs TH_LP S1 (J_shuf must be 0 for TH, nonzero for TH_LP). Report |BSC_TH,stat - BSC_DATA,stat| achieved in the pilot AND confirm and require <= 0.05 for S6 to be classified (otherwise UNMEASURABLE-MATCH).
